## 実装と検証の区別

- 先行手動振替：請求区分が未保存の状態で3個を指定して保存する。自動全量振替なし。
- 元数量訂正：同じ在庫IDの3→2、差1個は元のおやつ商品の使用可能数へ戻る。逆方向の新規振替不要。販売1＋再振替1がある場合の1個への減数を拒否。上限超過・理由なし・変更なしは拒否。
- 原価と請求：ロット原価、既存販売とその原価、請求・家庭数・手動単価・現金を維持。訂正が必要な用途数は利用者が別途明示指定する。差1個を共通単価へ自動割当しない。
- 逆方向の既存誤記録：明示取消の場合だけ元行を履歴へ退避。請求確定・家庭割当・再振替が残れば拒否。取消で空になった共通単価グループもID・名前・手動単価を保つ。無関係なグループは変更しない。
- 表示：集約は表示層のみ。ロットID・原価・家庭割当・既存グループを再作成しない。同商品でも原価違いは別に示す。
- 操作：先行振替は仕分け先頭の商品から直接開き、後段の区分を埋める必要がなくなる。数量訂正は商品直下から開き、数量・理由・保存で完了。集金の通常受取は1タップを維持し、一覧の過去説明を展開内へ移した。

ローカル：単体・DB161成功、既存2スキップ（追加のDB検証を実行中）。ビルド・文書検査成功。ローカルブラウザはOSのsocket起動制限で実行不能。Work4の画面・320/375/430px・Chromium/WebKitはPRのCIで実行し、画像も確認してから公開する。本人のiPhone実機合格は別途必要。

本番Supabase：読み取りの保全照合のみ。業務データ・現金・請求・振替・原価・Auth・migrationの書込み0件。数量差の原因は紙の実績未確認のため確定しない。公開と本人の実績訂正を同一視しない。
