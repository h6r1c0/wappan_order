# 現行業務・会計・保存の正本

この文書は**変わり得る業務仕様**を扱う。開発思想は [AGENTS.md](../AGENTS.md)、視覚と操作は [UX基準](ux-finish-checklist.md#今後の変更に適用するux基準)、検証手順は [DEVELOPMENT_CHECKS.md](DEVELOPMENT_CHECKS.md)。価格・日付・人物の例は現在の本番値や恒久的な定数を意味しない。仕様変更時は対象コードとテスト、確認できる利用者の判断を照合してここを更新する。

## 記録の帰属と計算

| 区分 | 根拠・記録 | 個人請求と年度計上 |
| --- | --- | --- |
| 個人注文 | 注文回の商品価格、実渡し数、カット代、欠品・取消 | 対象回の購入者へ請求。年度の通常売上・原価は対象回の状態に従う |
| 販売用 | 在庫ロット、販売数量・価格・原価、販売先、集金先回 | 後日個人請求、外部販売、即時入金を分け、販売先訂正で売上を重ねない。売れた分の原価だけ計上 |
| 行事 | 実使用数×対象商品の仕入単価 | 財政請求、通常の販売利益から除外。余剰を販売側へ振り替える際は原価も移す |
| おやつ | 商品別の実使用・原価と、家庭別の請求数・請求先を別々に保持 | 家庭の共通単価請求と職員の実原価による財政請求を分離。振替・在庫・利益の二重計上を防ぐ |
| その他販売 | 商品名・販売日・数量・単価・原価・受取状況 | パンの発注・在庫・個人集金と独立。原価0円は有効な数値で、原価未確定とは別。年度へ一度だけ計上 |
| 過去実績・利益調整 | 実績日または対象年度と根拠 | 架空の注文・仕入・現金受取を作らず、詳細実績との二重算入を防ぐ |

計算と保存の詳しい構造は [DESIGN.md](DESIGN.md)、`src/domain.js`、`src/commerce.js`、`src/snack-billing.js`、`src/other-sales.js`、関連する `tests/` を照合する。`null` の原価・価格を0円とみなして完了させない。家庭向け共通単価150円は過去の運用例で、将来の固定価格ではない。仕入単価・丸め方は対象期間のスナップショットと現行コードを確認する。

納品書税込合計が当該注文回の仕入を網羅し、同日の販売用在庫がすべて販売済みで行事等の原価が確定している場合、個人注文と販売用を合わせた利益は「両方の売上−納品書総額」で算出できる。販売用の個々の原価が不明でも全体利益だけは確定可能とし、個人注文と販売用の個別利益へ推計配分しない。未販売在庫や別日の売上・振替・セット販売がある場合は、該当する原価を確認する。販売用の購入者請求と個人請求外の支払済み販売を両方売上へ含め、同じ販売を再計上しない。受取・未収は利益に加算しない。`roundAccounting` と `tests/domain.test.js` を参照する。

## 注文回と価格改定

`rounds[].products` に対象回の商品・販売価格・原価などのスナップショットを保持し、各注文と集金はその回を参照する。商品マスターを更新しても過去回を遡及変更しない。注文回の価格を明示的に訂正する場合は差分・履歴・請求への影響を確認する。Excel取込や再編集でも使用済み回の価格を無断で上書きしない。月をまたぐ旧回の精算と新回の発注を並行できる。未公表の将来価格を本番へ仮登録しない。検証は `tests/domain.test.js`、`tests/excel-lifecycle.test.js`、`tests/commerce-line.test.js` など。

## テスト区分と年度実績

`round.test=true` の通常注文は `report` の年度通常売上・利益から除外され、販売用は紐づく `stock.test`、行事は `event.test`、おやつ請求は `event.test`、その他販売は記録自身の `test` で除外する。2026年9月11日は確認時点でテスト区分を維持する例であり、永続的な切替禁止ではない。

注文回の「注文の詳細」から利用者の確認を経て `setTest` で切替可能。関連する行事・販売用在庫にも区分を伝播し、集金先に紐づく販売記録との区分不一致は拒否する。切替の前には同日過去実績との二重計上、売上・原価・利益・財政請求、請求・受取・充当・訂正への影響を確認する。`collectionLive` はテスト回の集金債権を通常回の繰越へ含めるための別条件であり、年度実績を本番へ算入するスイッチではない。利用者の判断なしに本番の区分を変更しない。`docs/ACCEPTANCE.md` の9月11日例は初期の操作資料として読む。

## 請求・案内・受取・充当・訂正

- `collections` は通常注文・後日請求の販売・家庭向けおやつ請求を対象回で合算する。`billingReviews` の案内額と、`receivableItems` の既知の追加請求は現金受取を証明しない。商品・数量・単価の未確定は請求前照合と印刷前に示し、解決済み警告は未処理として繰り返さない。
- `collectionEntries` は受取原本。請求確認だけで作らない。通常の予定額全額受取は一操作、例外は受取額・理由・過去未収・預かり・未解決差額を区別する。受取・預かりの回収は新たな売上や利益ではない。
- `collectionAllocations` は**既存受取の充当先に関する別の判断**。受取金額だけで古い請求から順に割り当てない。複数債権に対する曖昧な一部受取は `unallocated` とし、請求別の支払済み表示を確定しない。複数先への金額分割は受取額と一致させる。一受取に有効な充当指定は一件。
- `collectionCorrections` は受取原本・支払済み確認の取消根拠。元記録と既存充当履歴は監査のため残すが、訂正済み受取・確認は `effectiveCollectionState` で現在の債権計算から除く。訂正済み受取に新しい充当指定を追加しない。`20261023073903` と `20261023075806` のDB migrationは参照・金額・一意性と訂正後の監査履歴を検証する。過去の受取内容を新コードの推測で書き換えない。
- 保存は `wappan_save` のrevision照合と履歴で競合・直接更新を防ぐ。本番作業中は開始時のrevisionを上書き対象として固定せず、保存直前に最新を再確認する。復旧用コピーに個人情報が含まれるため公開リポジトリに置かない。

代表的**回帰条件**（本番の現在残高ではない）：佐々木は今回1,020円＋過去50円→受取1,070円、 西尾は今回690円−預かり100円→受取590円、堀は請求2,510円・案内2,130円・既知差380円、余語は7月1,670円＋9月1,650円の未収から9月分だけ1,650円を充当したら7月分1,670円が残る。各テストでは事前状態・操作・期待結果を明示する。`tests/collection-workflow.test.js`、`tests/collection-database.test.js`、`tests/receivables.test.js` とブラウザーテストを参照する。

## 販売先・欠品・印刷

販売用の注文、納品、欠品・振替、割当、販売待ち、販売先不明を分ける。1個ずつ異なる先へ分割でき、購入者から複数商品もまとめられる。途中入力と訂正履歴を保護する。欠品は注文原本を保ち、確認した実渡し数を請求へ反映する。印刷できない条件は押す前に示し、案内済み帳票と訂正後帳票を混同しない。`src/shortages.js`、`src/collection-workflow.js`、`src/print-*.js`、対応テストを確認する。
