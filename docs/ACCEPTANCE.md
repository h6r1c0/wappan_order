# 9月11日分で実務と照合する

実際の9月11日の注文表・注文内訳・納品書・手計算結果は今回のリポジトリに含まれていません。したがって実データとの金額一致は、接続後に確認します。検証のために推測した注文内容を本番データとして入れてはいません。

## 入力

1. 「商品・購入者」→「Excelから取り込む」。9月の表を選び、商品名・税込価格・販売価格を見比べて登録する。ミルクスティック280円、黒糖ブレッド430円は個別価格を優先。
2. 購入者を登録。ホリ・浅野の固定注文は初期登録済み。ガレット・ドーナツ・湯種食パンは実価格の取込・登録後に候補になる。
3. 「注文」→「注文回を作る」→納品日 `2026-09-11`、**テスト入力をオン**。
4. 実際の購入者・数量を入力する。入力済みの0は固定注文で復活しない。
5. 「集金額」「発注数」を、従来の手計算と照合する。
6. 注文確定後、実際に欠品した人の数量を修正。「納品・精算」で実際の税込仕入総額を入れる。
7. 同じ納品書に行事・直接の園内販売がある場合、そのデータも**テスト区分**で登録し、「同じ納品書に…」から選ぶ。行事の振替商品を重複して選ぶ必要はない。

## 合わせる数字

| 確認するもの           | アプリの場所                                           |
| ---------------------- | ------------------------------------------------------ |
| 購入者別の請求         | 注文回→集金額。園内販売の後日請求は集金先注文回を選ぶ  |
| 商品ごとの注文数量     | 注文回→発注数                                          |
| 欠品後の通常販売額     | 注文回→納品・精算                                      |
| 通常注文の仕入額・利益 | 納品書総額と関連する行事・園内販売を登録後、納品・精算 |
| 行事使用分の財政請求   | 行事→実際の使用数×仕入単価                             |
| 園内販売の残数・販売先 | 園内販売→数量・記録を見る                              |
| 年度の過去実績・調整   | 集計→過去実績・調整                                    |

## 二重計上を避ける

- 9月11日分を過去実績として年度へ入れる場合、詳細なテスト注文は**テストのまま残す**。テスト注文と本番の過去実績を両方利益へ含めない。
- 詳細注文を本番へ切り替える場合は、先に同日の過去実績を削除またはテスト区分にする。
- 注文回の「日付・状態」でテスト区分を変更できる。関連する行事・園内販売も同じ区分へ連動する。関連データがある回は安全のため削除不可。テストとして保持すれば年度には入らない。
- 売り先を間違えた園内販売は、記録を取り消して正しい売り先で登録する。取消済み記録は残る。

## スマートフォンで確かめる点

- iPhoneで購入者名・数量を押しやすいか、キーボードなしで通常の数量入力ができるか。
- 「保存しました」の後、リロードして数量・金額が戻るか。
- 別の係の端末でログインし「最新を読込」で同じ内容が見えるか。
- 個人請求に、通常注文と園内販売が合算され、即時入金は含まれないか。
- 「行事20個→18使用→2振替」で請求が18個分のままか。
- 商品・注文・集計画面に横スクロールが生じないか。

実際のExcelレイアウト、9月11日の手計算一致、iPhone実機と実Supabaseでの複数端末確認が済んでから、本番注文へ移行してください。
