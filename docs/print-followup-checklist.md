## 再監査結果と実機制約
- 仕分け表は幅185mm、高さ235mmのグリッドと12mmの見出しで、A4印刷余白に約30mmの縦方向の余裕を持たせた。Chromium A4 PDFは販売1枚、16人（縦4枠混在）1枚、21人2枚（11人/10人）。WebKit印刷メディアでも表示を確認した。
- 販売表はヘッダーを12mm、名前下線を20mm・4列に変更。商品行の横罫線を除いた。商品スナップショットは変えず、帳票表示のみ「くるみパン【1個・9月11日資料】」を「くるみパン 1個入り」とする。
- 仕分けの「シナモンレーズン」は種類が不明なため「シナモンRクッキー」とした。既存の衝突検査とFAX順、注文あり購入者だけの抽出を維持。
- アプリの印刷入口に明示的な `alert` / `confirm` はない。`beforeunload` は未保存ダイアログまたは保存中だけで、通常の印刷では発火させない。iPhone Safariでは初回を直接 `print()`、以降は帳票を切り替え、Safariの共有→プリントを案内してスクリプト印刷の反復を避ける。WebKit相当の連打、別帳票、再操作テストでは不要なアプリダイアログは0回。
- iPhone Safari実機のプレビューと警告表示は本環境に端末がなく直接確認できない。WebKitデスクトップ相当とChromium PDFによる代替確認であり、実機で追加白紙が完全に解消したと断定しない。Android実機の印刷先も未確認。
- `npm test` は54成功・1スキップ、ブラウザ19成功、build成功。本番Supabaseへ書き込みなし。revision は開始時・公開後とも44。公開資産 `index-DGYWaukp.js` / `index-BVD5nnLX.css` を確認した。
